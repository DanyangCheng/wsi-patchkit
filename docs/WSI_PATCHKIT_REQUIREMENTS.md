# wsi-patchkit 读取与采样能力补充需求

## 1. 目标与评估基线

本需求用于补充 wsi-patchkit 的采样和流式读取能力。
目标是保留明确的物理坐标、像素采样和有效性语义，同时兼容库的现有调用方。

评估依据为 `types.py`、`geometry.py`、`stream.py`、reader Protocol、网格采样器和
相关测试源码。
现状结论不代表对所有 WSI 格式后端的完整运行验收。

## 2. 当前已有能力

以下能力应继续复用，无需重复实现：

| 能力          | 当前组件与说明                                                                  |
| ------------- | ------------------------------------------------------------------------------- |
| 文件格式路由  | AutoSlideReader；具体 Image/TIFF/OpenSlide/KFB reader                           |
| 原生区域读取  | SlideReader.read_region；起点为 level-0 整数像素，尺寸为选定层像素              |
| 切片元数据    | SlideMetadata/LevelInfo，包含尺寸、MPP、非等轴 downsample；支持 source_mpp 覆盖 |
| 原生层选择    | choose_level 的 nearest/finer；读取 helper 可传入 level                         |
| 网格采样      | GridPatchRequestSampler，支持 stride 和 align/drop 边缘策略                     |
| 基础重采样    | RGB nearest/bilinear/area；native 模式按最近邻处理                              |
| 基础常量填充  | PatchRequest.fill_value 单个 uint8 值                                           |
| 几何掩码      | read_aligned_patch_result 返回 PatchReadResult.valid_mask                       |
| 并行流        | 当前 PatchStream 已有 num_workers、max_pending 和 worker 独立 reader_factory    |
| 流输出顺序    | 并行读取按输入顺序产出，支持提前关闭迭代器及清理自有 reader                     |
| reader 所有权 | 显式传入的 reader 由调用方拥有；factory 创建的 reader 由流拥有                  |

## 3. 缺口与优先级

P0：完成等价接入前必须具备。P1：完整覆盖当前配置或增强运行保障所需。
优先级用于实施排序，不表示允许静默忽略未实现的配置。

| 编号 | 优先级 | 当前缺口                                                                                  | 需求结果                                       |
| ---- | ------ | ----------------------------------------------------------------------------------------- | ---------------------------------------------- |
| R01  | P0     | PatchRequest.x/y 被 int 转换，无法表达任意连续物理原点                                    | 明确支持连续物理采样网格                       |
| R02  | P0     | 原生区域 floor/ceil 后整体 resize，未保持任意请求的精确采样位置                           | 固定像素中心与插值坐标语义                     |
| R03  | P1     | 无 bicubic；同名插值缺少与接入方一致的细节约定                                            | 支持并定义 nearest/bilinear/bicubic，保留 area |
| R04  | P1     | 填充值仅单个标量，无 reflect                                                              | RGB 常量填充与反射填充                         |
| R05  | P0     | 掩码按取整画布矩形生成，和真实物理边界的像素中心判定不同                                  | 精确几何有效掩码                               |
| R06  | P0     | PatchStream 只返回 Patch(request, image)，不传递 valid_mask/读取几何；不暴露 level/policy | 流与直接采样共享完整结果及选层配置             |
| R07  | P0     | 画布固定采用 round，SlideSpec 与读取 helper 也固定该策略                                  | 一致且显式的画布舍入策略                       |
| R08  | P1     | 采样入口无输出/原生读取规模上限；max_pending 只限制任务数量                               | 分配前的读取规模限制                           |
| R09  | P1     | worker 创建 reader，但并行关闭在消费线程；清理异常可能替换原始错误；未显式关闭请求迭代器  | 可验证的线程归属与错误清理约定                 |
| R10  | P0     | 坐标/尺寸等 int 转换可静默改变输入；新采样规则缺少兼容模式                                | 严格校验与显式版本化行为                       |

R03/R04 中 bicubic、reflect 和 RGB 填充对应 SlideInfer 已公开的配置选项。
R01/R02/R05 对应内部连续物理坐标与有效性契约。
ROI、ownership 和推理配置校验仍由 SlideInfer 负责，不要求库认识这些任务类型。

## 4. 功能要求

### R01：连续物理采样网格

提供一个可公开使用的连续坐标采样请求，至少表达：

- 切片路径；物理原点 origin_um=(x,y)，允许负数和分数。
- 输出 MPP=(mpp_x,mpp_y)，两个分量可不同。
- 输出尺寸=(width,height)，正整数。
- 可选 source_mpp 覆盖。
- 可选明确的原生 level；未指定时使用公开的 level_policy。

坐标原点为 level-0 左上像素边界，X 向右、Y 向下，单位为微米。
读取完整物理范围为 `[x,x+width*mpp_x) × [y,y+height*mpp_y)`。
输出 shape 恒为 height/width，不因边界裁剪而缩小。

可新增请求类型或扩展现有类型，命名不作为验收条件。现有整数虚拟画布
PatchRequest 仍需可用，通过明确转换获得 origin_um=(x*target_mpp_x,y*target_mpp_y)。
传入分数 x/y 时不得静默截断；连续坐标入口必须保留其原点。

### R02：精确采样与几何结果

输出第 (row,col) 个像素中心必须对应：

```text
u_x = origin_x + (col + 0.5) * target_mpp_x
u_y = origin_y + (row + 0.5) * target_mpp_y
```

在原生 level 的中心索引坐标中，采样位置为：

```text
s_x = u_x / level_mpp_x - 0.5
s_y = u_y / level_mpp_y - 0.5
```

读取范围可为插值邻域扩展并取整数，但扩展不能改变输出的物理原点、步长和采样相位。
不得将扩展后的整块原生区域简单缩放，并把其结果继续标记为原请求的精确网格。
非整数/非等轴 downsample 必须保持正确的原生像素起点。

结果需返回实际 source_level 和输出网格信息，或等价的 output_to_slide_um 仿射变换。
原生 ReadPlan 的 location/size 不能代替输出网格描述。
原生 read_region API 保持现有 level-0 起点与层级尺寸语义。

### R03：插值语义

新精确采样入口至少支持以下模式，并公开说明：

| 模式     | 新精确采样语义                                                   |
| -------- | ---------------------------------------------------------------- |
| nearest  | 按 R02 的中心索引采样，整数索引选择 floor(s+0.5)，明确半整数取舍 |
| bilinear | 对中心索引的相邻像素执行双线性插值，保持分数相位                 |
| bicubic  | 用 Keys cubic、a=-0.5 的核；明确邻域、边界处理和 uint8 输出量化  |
| area     | 保留已有能力；说明支持的缩放方向、面积/滤波语义及适用数据类型    |

nearest/bilinear/bicubic 的有效区域内原生边缘采用钳位；reflect 采样见 R04。
浮点插值到 uint8 按 `clip(floor(value+0.5),0,255)` 量化。
如需抗混叠滤波，使用明确选项并文档化，避免同名模式随 backend 改变。
图像模式与 native/标签模式应分别规定；不得对类别 ID 进行连续插值。

该约定用于新采样行为。原有 resize 的滤波和取整规则需保留在兼容模式中。

### R04：填充

支持 constant 与 reflect：

- constant：RGB 接受标量或三通道整数值；标量广播为三通道。
- reflect：定义为原生像素中心索引上的反射，采用 numpy reflect 对应的
  不重复端点规则；长度为 1 的轴退化为复制。
- 任意远的负坐标/越界坐标都应可处理，受读取规模上限约束。
- 填充不改变输出几何；反射生成的像素仍属于 WSI 范围外的无效像素。
- constant 下完全越界的请求应直接返回填充图像和全 false 掩码，不进行像素 IO。
- reflect 下完全越界的请求可读取反射映射需要的原生像素，掩码仍全 false。

RGB 继续要求 uint8，灰度扩展为 RGB，RGBA 白色背景合成保持现有约定。
高位深图像的数值缩放不属于本次必需能力；不支持时明确报错。

### R05：精确几何有效掩码

新精确入口返回 HW bool 掩码，与图像 shape 的 H/W 相同。
设切片物理宽高为 W_um/H_um：

```text
geometry_valid[row,col] =
    (0 <= u_x < W_um) and (0 <= u_y < H_um)
```

像素中心恰好位于右/下物理边界时为 false。判定独立于 canvas 的 round/ceil、
插值核邻域与填充方式。返回的掩码只说明输出中心是否位于原始 WSI 范围。
不将组织筛选、ROI 孔洞、任务 ownership 或已完成推理 coverage 加入该掩码。

SlideInfer 在适配层将 geometry_valid 与 valid_region_sample/ROI 掩码相交。
因此库不必接受 TileContext 或 valid_region_sample。

### R06：流式结果与选层参数

PatchStream 或新公开结果流应直接产出图像、几何有效掩码和 R02 的网格/原生层信息。
可扩展 Patch 或新增结果模式，原有 request/image 访问方式保持兼容。
同一个请求的直接读取与串行/并行流结果必须一致。

明确原生 level 或 level_policy 的配置入口及优先级：显式 level 优先，
未指定时使用 level_policy。可以采用请求字段或流参数；多切片/不同层级请求
需要逐请求表达能力。当前 helper 的 level 参数应传到实际读取，不能由流丢弃。

持续满足已有的独立 reader、元数据缓存、顺序输出与 max_pending 行为。
公开定义 max_pending 的计数口径，包含排队、执行、完成等待输出和当前 yielded 请求；
消费者请求下一项前不再替换当前 yielded 请求所占的容量。
该限制不覆盖消费者自行保留的历史结果，也不等于完整内存字节预算。

### R07：画布与边缘策略

提供公开的画布舍入策略，至少包含兼容用 round 和完整范围规划用 ceil。
相同配置必须贯穿 SlideSpec 构造、virtual_canvas_size、读取裁剪与网格采样。
调用方自行传入 ceil 画布后，读取 helper 不得重新按隐含 round 画布裁剪。

ceil 表示计划范围覆盖完整物理 extent；末端像素仍须按 R05 的中心规则判断有效性，
不保证所有 ceil 画布像素为有效。align/drop 策略的含义保持现有定义。
保留 round 的现有默认结果，或通过明确的主版本变更调整默认值。

### R08：读取规模限制

新采样入口至少允许 max_output_pixels 和 max_read_pixels，均为可配置正整数。
前者在输出/掩码/坐标数组分配前检查；后者在原生 read_region 调用前检查，
计算范围须包括插值需要的邻域。超限错误报告请求、所选层、实际尺寸和上限。
可在分配前返回独立于 IO 的采样计划，便于调用方预算检查。

不得把 max_pending 宣称为 host_memory_budget：reader 缓存、解码、插值临时数组、
结果缓存和消费者保留的数据均影响实际峰值。默认上限及关闭上限的方式需文档化。
本次不要求库实现整个推理运行器的 CPU/GPU 字节预算。

### R09：流的生命周期和错误处理

现有有界并行流基础上补齐以下保障：

- 明确 reader 的线程归属。要求同线程生命周期的 reader 应在所属 worker 内关闭；
  通用 API 应支持该用法，或公开并验证跨线程 close 的必要条件。
- 正常结束、请求生成错误、factory 错误、读取错误、提前关闭均释放自有 reader。
- 已传入的借用 reader 不由流关闭；数据输出不因 reader close 或后续读取失效。
- 取消尚未开始的请求，等待已开始的 native IO 完成。不能宣称可强制中断第三方 IO。
- 当流拥有请求迭代器时关闭其 close()；请求迭代器的借用/拥有规则必须显式说明。
- 读取/请求生成的原始异常优先；清理失败不覆盖它。成功执行后的清理失败应传播。
- 提供清晰的 with/contextlib.closing 使用方式；空流不创建 factory reader。

不要求更改已有并行调度模型。当前顺序等待 Future 可能延迟后序错误暴露，
是否增加立即失败模式可另行设计；本次只要求明确失败语义和资源安全。

### R10：输入校验与兼容性

坐标/MPP 必须有限，MPP 严格为正；width/height/level 等整数不接受 bool 或分数。
新精确入口不得通过 int() 静默更改用户输入。
非法 level、选项、填充值、尺寸或不支持的数据类型应给出包含字段与原因的错误。

保留旧入口的既有输出结果和默认行为，新增精确模式或新入口进行接入。
如选择改变旧默认语义，应发布明确的兼容性变更与迁移说明。
新增可选结果字段须兼容现有 Patch(request,image) 等构造方式。
不得通过增加 reader 接口强制所有 vendor backend 重写采样算法。

## 5. 建议 API 结构

以下结构说明职责，不规定最终类名或签名：

```text
连续物理请求 / 旧 PatchRequest 的显式转换
    → 采样计划（原生层、所需区域、输出网格、规模检查）
    → 原有 SlideReader.read_region
    → 精确重采样 + 填充 + geometry_valid
    → 采样结果（request/image/valid_mask/grid/source_level）
    → 结果流（串行或已有有界并行调度）
```

同步单请求入口应成为流的公共基础实现，避免直接读取与流读取各写一套算法。
旧 helper 通过兼容模式保留历史行为，新入口明确提供精确采样语义。

## 6. 已验证的差异样例

测试图像原生 MPP=(1,1)，红通道沿 X 为 `[0,10,20,30,40,50,60,70]`，
其余通道为 0；选择 level=0。表中只列第一行红通道。
结果用于展示接入行为差异，不将所有差异归类为当前库的错误。

| 场景               | 请求参数                                               | 当前 SlideInfer                   | 当前库 helper                  |
| ------------------ | ------------------------------------------------------ | --------------------------------- | ------------------------------ |
| 对齐且不缩放       | origin=(1,1), MPP=(1,1), size=(3,2), nearest           | [10,20,30]                        | [10,20,30]                     |
| 整数比例下采样     | origin=(0,0), MPP=(3,1), size=(2,1), nearest           | [10,40]                           | [0,30]                         |
| 非整数比例         | origin=(1.5,0), MPP=(1.5,1), size=(3,1), bilinear      | [18,33,48]                        | [14,30,46]                     |
| 分数目标网格起点   | origin=(0.5,0), MPP=(1,1), size=(3,1), bilinear        | [5,15,25]                         | [0,10,20]，原点被取整为 0      |
| 左上常量填充       | origin=(-1,-1), MPP=(1,1), size=(3,2), nearest         | 图像与掩码一致                    | 图像与掩码一致                 |
| 输出中心落在右边界 | 裁图宽=3，origin=(0,0), MPP=(2,1), size=(2,1), nearest | image=[10,255]，mask=[true,false] | image=[0,10]，mask=[true,true] |

新精确模式应以 R01–R05 的公式作为验收依据；项目当前结果仅提供参考用例。

## 7. 验收矩阵

| 编号 | 场景                                             | 通过条件                                                                     |
| ---- | ------------------------------------------------ | ---------------------------------------------------------------------------- |
| A01  | 正/负/分数原点，非等轴 MPP                       | 输出网格及仿射变换与请求一致，不发生隐式取整                                 |
| A02  | 同比例、整数与非整数缩放，多个相邻请求           | 原生范围扩展不改变采样相位；相同原生层与点采样核配置下，相同物理中心结果一致 |
| A03  | nearest/bilinear/bicubic                         | 梯度图、脉冲图和固定参考计算覆盖核、半整数、边缘与量化                       |
| A04  | 非整数层级比，如 1000/333、800/271               | 不偏移到相邻 native 像素；网格与原生层信息正确                               |

| A12  | 同线程生命周期 reader                            | open/read/close 的线程 ID 符合公开约定                                       |
| A13  | 输出/原生读取超限；NaN/Inf/bool/分数整数参数     | 分配或 IO 前失败，错误可定位字段及请求                                       |
| A14  | RGB、灰度、RGBA、uint16                          | 已支持格式遵循公开规则；高位深 RGB 不隐式缩放                                |

坐标与浮点插值参考计算应明确容差；固定 uint8 测试按约定量化后逐像素比较。
先使用小型可解析梯度/脉冲图与模拟 reader，随后加入真实 PNG、TIFF 金字塔；
OpenSlide/KFB 的代表性样本按部署依赖提供后执行 backend 验收。

## 8. 实施顺序与交付

1. 明确连续坐标、精确采样、掩码和兼容模式契约，完成 R01/R02/R05/R10。
2. 实现共享的采样计划与单请求精确入口，补齐 R03/R04/R07/R08。
3. 让现有 PatchStream 传递完整结果和选层参数，完成 R06/R09 与并行回归。
4. 提供 API 文档、兼容性说明、测试及一个串行/并行读取示例。
5. SlideInfer 使用新入口，将采样算法与通用流调度移除，保留薄适配并运行回归。

验收通过后的职责：

| wsi-patchkit                                               | SlideInfer                                                          |
| ---------------------------------------------------------- | ------------------------------------------------------------------- |
| metadata/native IO、选层、采样、填充、几何掩码、通用流调度 | SlideInfo/TileRequest/ImageTile 转换及 TileContext 保留             |
| 连续输出网格与读取资源管理                                 | valid_region_sample/ROI 相交、ownership、context/halo 与 chunk 规划 |
| 库级数据类型和格式能力校验                                 | 预处理、批次、模型推理、融合、coverage 与交付                       |

库实现使用自身的请求与结果类型，不依赖 SlideInfer 的配置、任务或模型类型。
迁移完成以坐标、像素、掩码、顺序和生命周期回归为依据，而非仅以导入替换成功为依据。
