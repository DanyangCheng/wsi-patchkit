# 个人工作台

更新服务后，从查看器顶部的“个人管理”进入，或直接访问 `/personal`。
工作台复用现有登录、会话、CSRF 校验和切片目录授权。

## 页面与流程

1. **工作台**：查看可访问切片数、个人上传数、裁剪结果、任务状态与文件占用，
   继续最近查看的切片。文件占用包括回收站中的切片和未完成上传的数据。
2. **切片库**：搜索名称、项目、标签和备注，按项目筛选，按名称、文件大小或时间排序。
   打开详情可查看缩略图、尺寸、MPP、格式和来源；缺失的 MPP 显示为未知。
   分类、标签、备注和选区为账号私有，共享切片文件本身保持只读。
3. **上传管理**：批量选择或拖入单文件切片。分块上传显示进度，可暂停。
   网络中断或页面关闭后，重新选择同一个原文件即可继续；界面要求确认原文件，
   以免将同名同大小的其他文件拼接到已有数据上。上传完成后校验切片是否可读。
   中文文件名可用于显示，服务端保存路径使用安全名称或随机 ID。
   同名同大小的已有切片会提示是否重复上传；此提示不属于内容哈希去重。
4. **查看器中的裁剪任务**：在首页切片查看器打开“裁剪任务”，在当前切片中点击矩形的
   两个角，或逐点选取多边形并完成选区；可继续缩放和平移切片、移动矩形和编辑坐标。
   选区、已保存区域和批量网格叠加在切片上，随视口缩放和平移更新。
   在面板中设置原生层级、输出格式、目标 MPP 和批量图块参数，预览后提交任务。
   选区可保存名称、备注，裁剪参数可保存为模板。面板显示当前切片的任务进度，
   支持取消待执行任务和重试失败任务。
5. **切片详情与任务记录**：个人管理中的切片详情用于整理资料、查看选区并进入查看器。
   “任务记录”汇总各切片的等待、执行、完成、失败和取消任务。重试生成新的文件名，
   保留原任务记录。
6. **裁剪管理**：从个人管理进入，浏览、搜索、多选、下载或永久删除裁剪结果。
   可从结果定位回原始切片与裁剪区域。批量下载同时提供 `manifest.json`；
   也可单独导出全部或所选结果的 JSON 坐标清单。
7. **回收站**：仅个人上传的切片可以移入，执行中的关联任务结束后才允许操作。
   界面在操作前显示关联任务数量。移入后切片列表和图像接口暂停访问，文件和
   裁剪结果保留；恢复后继续访问。回收站不会释放文件空间。
8. **账号设置**：查看用户名、角色、状态、创建时间，修改显示名称、个人备注和密码，
   或退出所有设备。管理员可通过“管理用户与授权”进入已有的用户审核与目录授权页面。

## 裁剪参数与坐标

- `x/y/width/height`、图块尺寸和步长均使用所选原生层级像素。
- 步长小于图块尺寸时产生重叠；边缘可选择跳过不足一块的区域或裁至选区边界。
- 多边形用于筛选中心点位于其内部的批量图块。单次区域裁剪输出选区的外接矩形。
- 组织过滤根据最大边 1024 像素的预览图估算：颜色通道差大于 15、最暗通道小于 235、
  最亮通道大于 20 的像素视为组织。此规则适合有颜色的组织预筛选，不能代替病理标注；
  最低组织占比设为 0 可关闭。纯背景可能使预览结果为 0。
- 目标 MPP 为 0 时输出所选原生层级像素；设为 `0.001–1000 μm/px` 时，按已知的
  level-0 MPP 重采样输出。缺少 MPP 的切片会提示使用原生层级；不会猜测物理分辨率。
- 执行前预览网格、图块数和未压缩 RGB 像素量。实际编码文件大小取决于内容和格式。
  每次最多规划 512 个候选网格，每张输出仍遵守服务端 `max_output_pixels` 限制。
- 参数模板保存层级、图块尺寸、步长、格式、边缘处理、组织占比和目标 MPP。
  区域坐标通过选区单独保存，便于在不同切片上复用参数。

清单的 `coordinate_system` 为 `selected_native_level_pixels`，记录源切片 ID、原生层级、
区域坐标、层级下采样倍数、源尺寸、源 MPP、输出 MPP、输出尺寸和文件名。
图像文件名是相对于当前账号裁剪目录的路径。更新前产生的历史图像仍可浏览、下载；
没有来源记录的图像在清单中标记为 `unknown_legacy_file`。

查看器支持 `/?slide=ID&crop=1` 打开切片和裁剪面板，以及带
`level/x/y/width/height` 参数或 `region=选区ID` 的来源定位链接。
坐标会先验证层级和范围，再显示裁剪框并定位视口。

## 账号与数据持久化

密码需 12–1024 个字符，页面要求确认新密码并检查当前密码。
服务端沿用 PBKDF2 密码哈希、尝试频率限制和 CSRF 校验；修改成功后撤销该账号所有会话，
跳转重新登录。显示名称与登录用户名分开保存，修改资料不影响登录名和权限。

设置了 `PATCHKIT_AUTH_DB` 时，工作台记录存放在同一个 SQLite 文件的独立数据表内。
现有 Compose 的认证数据卷会同时保存个人资料、分类、选区、模板、上传会话和任务历史。
使用 `create_app()` 且未指定认证数据库时，记录放在裁剪目录同级的
`.workbench/<裁剪目录名称>.sqlite3`。新建数据库文件权限为 0600。
上传内容仍保存在上传目录，结果仍保存在裁剪目录；备份时应一并保存数据库与这些目录。

任务队列使用服务进程内的工作线程，部署时使用一个应用进程。
重启后保留历史任务，原先等待或执行中的记录标为中断失败，可手动重试。
已上传分块的偏移从临时文件实际大小读取，重启后可继续上传。
每个分块最多 8 MiB，每个账号最多保留 20 个未完成上传会话；单张总大小沿用
`--max-upload-gb`。可在上传队列移除未完成项，清理已接收的临时数据。

`--no-auth` 模式用于本机开发，共享本地工作空间，账号资料修改和密码功能不启用。
